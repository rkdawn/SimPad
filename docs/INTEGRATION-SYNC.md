# 平板功能集成同步说明：1.0.2

用于已经集成 SimPad 微信逻辑的项目。此说明仅覆盖兼容修正，不要求替换宿主项目框架、界面或设置实现。

微信的逐版本状态见 [兼容说明](WECHAT-COMPATIBILITY.md)。

## 必须一起同步的内容

| 文件 | 变更 |
|---|---|
| `WeChatProfiles.kt` | 增加 Play 8.0.80／3200 完整配置；3183使用`inner`，3200使用`tablet`设备目标 |
| `MethodGraph.kt` | 保留完整关系校验，并将配置选定的设备目标角色写入计划 |
| `HookPolicy.kt` | 计划增加`hookTarget`；微信有独立规则版本；校验、序列化与反序列化完整同步 |
| `CodeIdentity.kt` | 计划指纹按目标应用选择相同的规则版本 |
| `PlanBinder.kt` | 根据计划角色绑定已有的`wechat_device`，而非固定绑定内层方法 |
| `HookEntrance.kt` | 日志同时输出实际`deviceRole`和设备方法，支持缓存命中后的核查 |

以上文件位于 `app/src/main/java/io/github/rkdawn/simpad/`。集成时只替换接收项目自己的命名空间／适配器，不改微信描述符。

## 不可遗漏的缓存问题

8.0.80的`vk.C()`先读`vk.g`，缓存命中则不再调用`vk.b(...)`。只同步新版混淆映射而继续Hook内层，会重现1.0.1问题。

设备目标必须存入方法计划缓存。旧计划缓存不得默认继续沿用旧内层目标；微信计划规则版本同时用于指纹与记录解码。独立模块更换namespace不会自动使另一个项目自己的缓存失效，接收项目必须更新其缓存合同。

不要将新版目标直接应用到所有旧微信版本。8.0.79／3183保留原来的内层行为。

## 保持不变的行为

- 每次设备回调先调用原方法，保留原异常及副作用；再使用聊天调用例外决定返回值。
- 不主动写入、清空或强制赋值微信共享平板结果缓存。
- 设备判断和登录入口仍只有两个业务 Hook，不同时Hook内外两层以堆叠兜底。
- 登录入口仍为After处理；不将认证失败改成功，不隐藏网络或账户失效提示。
- 早期启动前置安装、启动后输入复核、整批失败回滚和代码身份校验保持。
- legacy Xposed或其他框架适配器必须保证原方法恰好执行一次；不得直接复制modern API调用到不兼容框架。

## 接收项目验证清单

1. 保留3183真实事实回归，并确认其设备目标没有变化。
2. 增加3200真实事实回归，确认外层目标经过完整关系校验选中。
3. 模拟“内层首次写false，外层后续直接读缓存”的路径：旧内层Hook被绕过，新外层Hook在冷缓存和热缓存均生效。
4. 验证聊天调用、原调用次数、异常传播和共享缓存未被模块写入。
5. 验证旧方法计划失效、新目标缓存可往返保存，非微信功能不受影响。
6. 构建并检查入口、依赖、签名与测试数据不入包。
7. 单独完成集成版实机验收：设备登录入口、登录、强停后状态、聊天输入与后台消息。

可以复用的测试：`WeChatPlay3200Test.kt`、`FormalThreePointTest.kt`、`HookPolicyTest.kt`、`StartupCacheScopeTest.kt`及`wechat-play-3200.tsv`。集成版测试数量不必与独立模块一致，但必须覆盖上述行为。

独立 SimPad 的测试和实机日志不等同于集成项目已经验收。测试时应只启用一个平板实现，避免两个模块同时Hook相同目标。
