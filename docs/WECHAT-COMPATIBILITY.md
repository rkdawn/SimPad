# 微信版本兼容说明

兼容性以**发布渠道、versionName 和 versionCode**共同区分。以下明确适配的是微信 Google Play 版本（包名 `com.tencent.mm`），不代表同名的其他渠道安装包或后续热补丁都已验证。

## 各版本适配情况

| SimPad 版本 | 微信 Play 8.0.79／3183 | 微信 Play 8.0.80／3200 | 发布状态 |
|---|---|---|---|
| 1.0.0 | 已有专用映射 | 通用匹配因缓存歧义失败 | 历史正式版 |
| 1.0.1 | 保留原适配 | 新增映射但仍可能被缓存绕过 | 本地候选，未单独发布 |
| 1.0.2 | 保留原内层目标 | 修复外层缓存绕过 | 已撤为草稿，附件留档 |
| **1.10** | **保留原内层目标** | **沿用已修复的外层缓存 Hook** | **当前正式版，versionCode 4** |
| 其他版本 | 未明确验证 | 未明确验证 | 不保证自动兼容 |

其他版本仍可尝试现有通用结构定位，但不属于已明确验证的兼容版本。匹配失败或存在歧义时，不会随意选择首个候选，也不会借用其他版本的混淆名称。

- **8.0.79／3183：** 原设备判断目标保持不变；本版没有新的微信行为修改。
- **8.0.80／3200：** 外层缓存判断 Hook 由1.0.2引入，1.10原样沿用；005327日志记录外层Hook安装及随后页面创建，但完整认证、长期保持尚未验收。
- **1.10未单独安装到手机重测。** 本次仅按用户指定更新正式版本名与构建号，微信业务源码与1.0.2发布版相同。

## 实测及代码验证边界

- **8.0.79／3183：** 原内层设备 Hook 目标保持不变；旧版映射回归通过，不表示这次重新完成了该版的全量实机测试。
- **8.0.80／3200：** 完整六分包静态分析、真实DEX事实和缓存优先路径测试通过。用户005327日志记录 Hook 安装及`LoginAsExDeviceUI`、之后的主界面/聊天页创建，但完整认证、长期保持未验收。
- **1.10未单独安装到手机重测。** 与1.0.2的微信业务逻辑相同，本次改的是正式版本名称及构建号。

| 角色 | 8.0.79／3183 | 8.0.80／3200 |
|---|---|---|
| 内层设备判断 | `com.tencent.mm.ui.ok.C(nw5.w0)` | `com.tencent.mm.ui.vk.b(pw5.w0)` |
| 外层包装方法 | `com.tencent.mm.ui.ok.B()` | `com.tencent.mm.ui.vk.C()` |
| 实际设备 Hook | **内层** | **外层** |
| 登录入口 | `fc1.h0.a(View, androidx.lifecycle.y)` | `wc1.h0.a(View, androidx.lifecycle.y)` |
| 结果字段（仅定位元数据） | `ok.f` | `vk.g` |

8.0.80的外层方法在结果缓存非空时直接返回，跳过内层判断。因此仅拦截内层返回值无法覆盖后续缓存命中；1.0.2将已有设备 Hook 移到外层，不增加第三个业务 Hook，不主动写入微信结果缓存。

两种版本均保留原方法调用、聊天输入兼容判断、登录入口 After 处理、启动前置安装及启动后输入复核。

## 升级与日志核对

1. 覆盖安装当前 SimPad，保持在框架中启用微信作用域。1.10的versionCode为4，高于旧1.0.2的3；包名和签名相同，静态检查允许覆盖，但未在设备实际安装验证。
2. 彻底结束微信进程后重新打开，使新 Hook 生效；普通切回前台不一定重载模块。
3. 不要同时启用其他修改平板身份的模块。
4. 无需清微信数据；旧版微信方法计划会按新规则重新定位，钉钉和企业微信计划规则不变。
5. Hook安装日志或1.0.2页面记录不能替代1.10自己的实机认证验收。

8.0.80／3200正常绑定时应记录：

```text
WECHAT_MODULE_READY version=1.10
WECHAT_PLAN ... deviceRole=tablet device=Lcom/tencent/mm/ui/vk;->C()Z
INSTALLED WECHAT ... hooks=2
WECHAT_STARTUP_BEFORE after_inputs_confirmed
```

若仍不正常，反馈微信渠道／版本号／构建号、模块版本、失败步骤及对应日志。启动时的网络请求告警本身不能证明平板适配失败；需要与实际页面和认证结果分开判断。
